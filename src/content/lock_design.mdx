## What is Lock Design?

<div className="ld-intro">
  <div>
    <p className="ld-text">Lock Design is a built-in protection feature in Think4ever that lets you freeze the core design layers of your project once they reach a confirmed or approved state. When locked, concepts, UI screens, flows, and requirements cannot be edited, moved, or deleted by accident.</p>
    <p className="ld-text">This helps teams establish clear stage gates, protect signed-off deliverables during developer handoff, and ensure that AI agents or team members do not introduce unintentional changes during implementation sprints.</p>
    <div className="ld-subhead">Best for:</div>
    <ul className="ld-list">
      <li>Fast-track sign-off and client approval before development handoff.</li>
      <li>Preventing drift between approved designs and ongoing developer sprints.</li>
      <li>Maintaining team alignment when multiple collaborators work on the same project.</li>
    </ul>
  </div>

  <aside className="ld-glance">
    <div className="ld-glance-title">At a glance</div>
    <div className="ld-glance-row">
      <span className="ld-glance-label">Where:</span>
      <span className="ld-glance-value">Project menu (top right context menu)</span>
    </div>
    <div className="ld-glance-row">
      <span className="ld-glance-label">Who can unlock:</span>
      <span className="ld-glance-value">Project Owner or Company Administrator</span>
    </div>
    <div className="ld-glance-row">
      <span className="ld-glance-label">Lock status:</span>

## Tips and best practices

<div className="ld-grid-3">
  <div className="ld-card">
    <h4 className="ld-card-title">Lock after sign-off</h4>
    <span className="ld-card-text">Freeze designs as soon as stakeholders sign off to establish an unambiguous contract.</span>
  </div>
  <div className="ld-card">
    <h4 className="ld-card-title">Review first</h4>
    <span className="ld-card-text">Run a final check across requirements and flows prior to engaging the lock.</span>
  </div>
  <div className="ld-card">
    <h4 className="ld-card-title">Keep coding</h4>
    <span className="ld-card-text">Continue development freely; locking does not block coding or implementation workflows.</span>
  </div>
  <div className="ld-card">
    <h4 className="ld-card-title">Tell your team</h4>
    <span className="ld-card-text">Notify collaborators when a baseline is locked so everyone references the same state.</span>
  </div>
  <div className="ld-card">
    <h4 className="ld-card-title">Plan changes</h4>
    <span className="ld-card-text">Batch future design modifications into planned review cycles before unlocking.</span>
  </div>
  <div className="ld-card">
    <h4 className="ld-card-title">Export a baseline</h4>
    <span className="ld-card-text">Export your locked blueprint or <code className="ld-code">.thinkp</code> archive to preserve a milestone snapshot.</span>

## Troubleshooting and FAQ

<div className="ld-faq">
  <div className="ld-faq-item">
    <h4 className="ld-faq-q">Why can&apos;t I see the Lock Design option?</h4>
    <span className="ld-faq-a">You must be a Project Owner or Company Administrator to access the lock controls.</span>
  </div>
  <div className="ld-faq-item">
    <h4 className="ld-faq-q">Why did the modal tell me someone else is editing?</h4>
    <span className="ld-faq-a">If another team member has unsaved active edits, resolve those changes before locking.</span>
  </div>
  <div className="ld-faq-item">
    <h4 className="ld-faq-q">I locked it by mistake. Can I undo it?</h4>
    <span className="ld-faq-a">Yes. Simply choose Unlock Design from the project menu if you have appropriate permissions.</span>
  </div>
  <div className="ld-faq-item">
    <h4 className="ld-faq-q">Can I still use the API or MCP when locked?</h4>
    <span className="ld-faq-a">Yes. Read operations and dev tools continue to function normally.</span>
  </div>
  <div className="ld-faq-item">
    <h4 className="ld-faq-q">Does locking stop developers from coding?</h4>
    <span className="ld-faq-a">No. Developers can build and edit code in Developer Mode or via connected IDEs over MCP.</span>
