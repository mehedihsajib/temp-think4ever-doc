## Screen Look Check

<span className="ga-section-sub">Does every built screen look like the screen that was designed for it?</span>

<p className="ga-text">Screen Look Check is one more layer of Gap Analysis. Gap Analysis tells you what is built and what is missing. Screen Look Check looks at the pictures: it puts each designed screen next to the same screen of the built application, lists every difference in look, and lets you send the differences you choose to the developer agent to fix.</p>

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/01-window-overview.png" alt="The Screen Look Check window" />
  <figcaption className="ga-caption">The Screen Look Check window: the screens on the left, the design and the built screen side by side, the problems below.</figcaption>
</figure>

### 1. How to open it

<p className="ga-text">There are two ways.</p>

<div className="ga-steps">
  <div className="ga-step"><span className="ga-step-num">1</span><div><span className="ga-step-text">In the top menu open <strong>MCP &amp; Tools</strong> and choose <strong>Screen Look Check</strong> under Quality.</span></div></div>
  <div className="ga-step"><span className="ga-step-num">2</span><div><span className="ga-step-text">Or open <strong>Gap Analysis</strong> and press <strong>Screen look</strong> at the top of its window.</span></div></div>
</div>

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/02-menu.png" alt="Screen Look Check in the Quality menu" maxWidth="360px" />
  <figcaption className="ga-caption">Screen Look Check in the menu, next to Gap Analysis.</figcaption>
</figure>

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/03-screen-look-button.png" alt="The Screen look button in the Gap Analysis window" />
  <figcaption className="ga-caption">The Screen look button in the Gap Analysis window.</figcaption>
</figure>

### 2. How to start a check

<div className="ga-steps">
  <div className="ga-step"><span className="ga-step-num">1</span><div><span className="ga-step-text">Press <strong>Check the screens</strong>.</span></div></div>
  <div className="ga-step"><span className="ga-step-num">2</span><div><span className="ga-step-text">Choose which screens to check: all designed screens, only the screens that had problems, or your own choice.</span></div></div>
  <div className="ga-step"><span className="ga-step-num">3</span><div><span className="ga-step-text">If your application asks to sign in, type a test account. It is used for this check only and is not saved. If the application&apos;s own data already has a demo account, the check finds and uses it by itself.</span></div></div>
  <div className="ga-step"><span className="ga-step-num">4</span><div><span className="ga-step-text">Press <strong>Start the check</strong>.</span></div></div>
</div>

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/04-start-panel.png" alt="The Check the screens start panel" maxWidth="360px" />
  <figcaption className="ga-caption">The start panel.</figcaption>
</figure>

<p className="ga-text">You do not have to start the application yourself. If it is not running, the check starts it, takes the pictures and stops it again.</p>

<p className="ga-text">While the check runs you see how many screens are done. You can close the window and come back later; the check goes on.</p>

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/05-check-in-progress.png" alt="A Screen Look Check in progress" />
  <figcaption className="ga-caption">A check in progress. Screens that are being compared show a small circle.</figcaption>
</figure>

### 3. How to read the result

<p className="ga-text">Every screen has its own card.</p>

<ul className="ga-list">
  <li><strong>Design, the target</strong> is the picture of the screen as it was designed.</li>
  <li><strong>Built application</strong> is the picture of the same screen in the running application, with its address.</li>
  <li>The <strong>percentage</strong> says how close the two look.</li>
</ul>

| Match | What it means |
| :--- | :--- |
| <span className="ga-match ga-match--green">90 to 100 %</span> | The same look. Only small polish is left, or nothing. |
| <span className="ga-match ga-match--lime">70 to 89 %</span> | The same structure, with differences in style that you can see. |
| <span className="ga-match ga-match--orange">40 to 69 %</span> | Parts are missing or laid out in another way. |
| <span className="ga-match ga-match--red">Below 40 %</span> | A different screen. |

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/06-one-screen.png" alt="One screen card with the design and the built screen" />
  <figcaption className="ga-caption">One screen: the design on the left, the built screen on the right. Here the row of filter chips is missing and the heading is different.</figcaption>
</figure>

<p className="ga-text">Click a picture to see both pictures large, side by side.</p>

<figure className="ga-figure">
  <DocImage src="/images/gap-analysis/screen-lock-check/07-both-pictures-large.png" alt="Both pictures large, side by side" />
  <figcaption className="ga-caption">Both pictures large.</figcaption>
</figure>

<span className="ga-subhead">The problems</span>

<p className="ga-text">Under the pictures is the list of problems found on that screen. Each problem says:</p>

<ul className="ga-list">
  <li>how serious it is: <strong>High</strong> (a part is missing or the layout is different), <strong>Medium</strong> (a clear difference in style) or <strong>Low</strong> (small polish);</li>
  <li><strong>Design</strong>: what the designed screen shows;</li>
  <li><strong>Built</strong>: what the built screen shows;</li>

### 8. Good to know

<ul className="ga-list">
  <li><strong>Screens without a design.</strong> Only screens that have a built UI design are compared. A screen without one is shown as &quot;No design&quot;.</li>
  <li><strong>When no picture can be taken.</strong> Some screens cannot be opened in a browser: a mobile or desktop application, or a screen behind a sign-in when no test account is known. The check then compares the design with the code of the screen and says so on the card (&quot;compared through the code&quot;). It is more careful there and reports only what the code proves.</li>
  <li><strong>Sign-in screens.</strong> The application&apos;s own sign-in and register screens are opened signed out, the other screens signed in.</li>
  <li><strong>Parts that cannot be compared.</strong> A dialog that opens only after a click, or the part of a long page below the picture, is listed under &quot;Could not be compared&quot; and is not counted as a problem.</li>
  <li><strong>Your design stays as it is.</strong> The check never changes the concept or the UI screens. Fixes are made in the code of the application, by the developer agent, after you confirm them.</li>
  <li><strong>Earlier checks are kept.</strong> Each screen shows its newest result, and the result before it is used for the comparison.</li>
</ul>
